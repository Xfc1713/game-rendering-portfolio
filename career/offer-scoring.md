# Offer 评分表（三问 + 加权）

> 在 **方向未定型** 时选首份工作，用同一套标准比较多个 offer，避免只看薪资或公司名气。

## 使用步骤

1. 每拿到 1 个 offer，复制下方「单次评分表」填一行
2. 三个核心问题各打 1～5 分，再填附加项
3. 算 **加权总分**，结合 [career-roadmap-18m.md](../docs/career-roadmap-18m.md) 看更利于 A/B/C/D 哪条分支

---

## 三个核心问题（各 1～5 分）

### Q1：C++ / 引擎 / 性能 exposure（权重 35%）

| 分数 | 标准 |
|------|------|
| 5 | 日常写 C++，或深度用 Unity/UE/自研引擎，经常做性能与渲染相关讨论 |
| 4 | 游戏客户端，定期接触引擎与 Profile，语言以 C++ 或 C# 为主 |
| 3 | 游戏工具/脚本/测开，部分 C++/Python 工具，能旁听听引擎组 |
| 2 | Java/Go 后端为主，与游戏/图形无关 |
| 1 | 纯手工测试、无代码或几乎不写代码 |

**利于分支**：5→A；4→A/B；3→B/D；2→C；1→D（且不利长期转 A）

---

### Q2：Mentor / 代码评审 / 发布流程（权重 35%）

| 分数 | 标准 |
|------|------|
| 5 | 明确 mentor、Code Review、规范 Git 流程、有版本发布节奏 |
| 4 | 有评审但不稳定，或团队小但负责人愿带 |
| 3 | 有流程但流于形式，主要靠自学 |
| 2 | 外包式交付，少评审、需求变动混乱 |
| 1 | 无导师、无规范、无成长反馈 |

**说明**：此项决定 **2 年后工程能力**，比公司品牌更重要。

---

### Q3：业余副线时间（权重 30%）

| 分数 | 标准 |
|------|------|
| 5 | 双休稳定，加班少，每周可稳定 8～10h 给作品集 |
| 4 | 偶尔加班，每周约 6～8h |
| 3 | 单休或旺季加班，每周约 4～6h |
| 2 | 大小周/996 倾向，每周 < 4h |
| 1 | 入职即高强度加班，无暇副线 |

**说明**：Q3 过低会 **杀死分支 A**，即使 Q1 很高也难坚持 18 个月副线。

---

## 附加项（每项 ±0.5～1 分，可选）

| 附加项 | 加分 | 减分 |
|--------|------|------|
| 游戏行业 / 上海目标城市 | +0.5 | 非游戏且你志在图形：-0.5 |
| 岗位 JD 含「渲染/图形/引擎」 | +1 | — |
| 培训协议/不合理违约金 | — | -1 |
| 薪资显著低于市场价且无成长 | — | -0.5 |
| 团队技术栈与 [resume-backend.md](resume-backend.md) 完全匹配 | +0.5（冲 C 时） | — |

---

## 计算公式

```
加权总分 = Q1×0.35 + Q2×0.35 + Q3×0.30 + 附加项合计
```

| 总分区间 | 建议 |
|----------|------|
| ≥ 4.2 | 优先考虑，利于保留 A/B 选项 |
| 3.5～4.2 | 可接受，需刻意保护副线时间 |
| < 3.5 | 谨慎：除非生存必需，否则不利于 18 月路线图 |

---

## 分支倾向速查（Q1 为主）

| Q1 分 | 18 个月后更可能 |
|-------|-----------------|
| 5 | A 渲染 |
| 4 | A 或 B |
| 3 | B 或 D（测开） |
| 2 | C 后端 |
| 1 | D QA（难转 A） |
